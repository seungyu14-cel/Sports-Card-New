# KBO 근거 검색·카드별 수정 — 첫 개발 목표

## 지원 범위

`/local`에서 KBO를 선택하면 기존 7장·10장 제작에 자동 적용됩니다.

1. MD의 모든 구간을 읽고 AI가 고른 구절 번호에 해당하는 원문을 근거로 가져옵니다.
2. LangChain Document와 Retriever로 현재 업로드의 근거를 검색합니다.
3. LangGraph가 카드별 `검색 → 작성 → 검수 → 필요 시 수정 → 재검수`를 실행합니다.
4. 최초 작성 이후 수정은 카드당 최대 2회입니다. 정상 카드는 다시 작성하지 않습니다.
5. 표지·본문·마무리와 캡션·게시 제목·해시태그·숏폼 훅을 검수합니다.
6. 끝까지 통과하지 못하면 화면에 **검토 대기**와 해당 원고·근거 기록 링크가 표시됩니다.
7. 모든 검수를 통과한 뒤 기존 PNG와 Work 전달 ZIP을 생성합니다.

LangChain Core의 Retriever/Runnable과 실제 LangGraph StateGraph를 사용합니다.
이번 검색은 **현재 업로드의 인용을 대상으로 한 키워드 검색과 근거 ID 필터**입니다.
벡터 임베딩·Supabase 뉴스룸 통합·외부 공식 경기 조회는 이번 단계에 포함되지 않습니다.
추가 API 키나 임베딩 모델 다운로드는 필요 없습니다. 기존 Ollama 모델을 사용합니다.
문서별 source SHA-256과 계획된 근거 ID로 범위를 제한하므로 다른 업로드나
계획에 없는 경기의 비슷한 숫자를 수정 근거로 끌어오지 않습니다.

**원문에 충실한지 검사하는 기능이며, MD 자체가 참이라는 뜻은 아닙니다.**
근거 상태는 `uploaded_source_only`입니다. 공식 경기 결과와의 대조는 사람이 수행해야 합니다.
MD에 서로 모순되는 내용이 있으면 먼저 원문을 정리하세요.

## Windows 실행

최신 변경이 들어 있는 브랜치에서 실행 중인 서버를 `Ctrl+C`로 종료하고
`start.bat`를 실행합니다. 설치 스크립트가 새 의존성을 설치합니다.
변경 브랜치가 main에 아직 병합되지 않았다면 먼저 해당 브랜치를 체크아웃하세요.
로컬 수정이 있으면 보관하고, 강제 덮어쓰기는 하지 마세요.

수동 실행:

```powershell
python -m pip install -e ".[dev]"
python -m sports_card_news.webapp --open-browser
```

1. `http://127.0.0.1:8787/local`에서 `LOCAL AI READY`를 확인합니다.
2. KBO, 편집일, 7장 또는 10장을 선택합니다.
3. 출처와 사실을 확인한 MD를 넣고 제작을 시작합니다.
4. 진행 문구의 `팀·수치·단위·승패 관계 재검수`, `오류 항목만 수정`을 확인합니다.
5. 완료 후 **원문 근거 검수 기록** 또는 전달 ZIP에서 근거와 수정 이력을 확인합니다.
6. 검토 대기이면 링크를 열어 잘못된 문장과 검색된 원문을 비교한 뒤 MD를 수정해 새로 제작합니다.

검토 대기 작업은 자동으로 발행되지 않으며, 완성 목록에도 들어가지 않습니다.
중간 JSON은 검토용 초안입니다. 실행 재개·부분 수동 승인 기능은 아직 없습니다.
네트워크·모델 장애는 `실패`로, 수정 한도 후 근거 부족은 `검토 대기`로 구별합니다.

## 사실 관계 검수 원칙

숫자가 있는 문장 전체를 원문과 일치시키던 조건을 제거했습니다.
조사·어미 변경, 문장 분리, 명확한 약칭, 같은 사실의 요약을 허용합니다.
예를 들어 원문의 `6경기를 모두 이겨`를 `6전 전승`으로, `승점 18점을 기록했고`를
`승점 18점을 기록했다`로 쓴 것만으로는 수정 대상이 되지 않습니다.

검수는 두 단계이며, 숫자 존재 검사만으로 통과할 수 없습니다.

1. **수치 사전검사**: 선택된 근거에 없는 수치는 먼저 차단합니다. 8과 18, 1.25와 2.15를 구분합니다.
   1,250/1250, .300/0.300 같은 표기 차이는 같은 값으로 취급합니다. 원문에 없는 계산 결과는 허용하지 않습니다.
2. **문구별 관계 검수**: 모델이 표지·본문·핵심 수치·캡션·태그·훅을 빠짐없이 검수합니다.
   각 문구에 근거를 연결하고 팀·선수(subject), 수치·부호(quantity), 단위·기록 종류(unit),
   경기·상대·시점(context), 승패·인과관계(outcome), 긍정·부정(polarity)을 각각 판정합니다.
   숫자를 한글로 쓴 문구와 숫자가 없는 주장도 이 단계를 거칩니다.

코드는 판정 누락·중복, 제공되지 않은 근거, 하나라도 실패한 관계를 차단합니다.
문구가 인용한 근거 안에 해당 수치가 있는지도 다시 검사합니다. 다른 문구의 근거에 같은 숫자가 있다는 이유로 승인하지 않습니다.
예: 김투수 8탈삼진/박투수 9탈삼진이 있더라도 `김투수 9탈삼진`은 주체와 수치 관계 검수 대상입니다.
`KIA가 LG에 6-4 승리`와 `LG가 KIA에 4-6 패배`처럼 팀 순서와 점수를 함께 바꾼 동등 표현은 허용합니다.

긴 캡션은 문구를 나눠 모든 내용을 검사하며, 요청당 최대 3개 문구와 실제 입력 예산으로 크기를 제한합니다.
통신이나 응답 형식 오류는 기술 오류로 남기며, 부분 검수 내용을 보존합니다.
실패한 카드만 최대 두 번 수정하는 기존 흐름은 유지합니다.

**관계의 의미 판단은 로컬 모델이 수행하므로 오판 가능성이 있습니다.**
코드는 검수의 누락과 범위 이탈을 막지만, 팀·선수의 관계를 별도의 공식 데이터로 증명하지 않습니다.
모델이 판단을 잘못하면 오류가 통과할 수 있으므로 게시 전 사람의 검토가 필요합니다.
이번 변경은 기존 KBO 카드 검수 경로에 적용되며, 다른 리그로 검수 범위를 확장하지 않습니다.

## 기록 파일

`output/studio/<session-id>/`에 저장합니다.

| 파일 | 내용 |
|---|---|
| `source.md` | 업로드한 원문 |
| `evidence-index.json` | 인용, 근거 ID, 원문 해시, 원문 구간·정규화 인용 위치 |
| `grounding-card-02.json` 등 | 실제 검색 결과, 최초 원고, 문구별 관계 판정·근거 연결, 오류, 수정본, 재검수 |
| `grounding-social.json` | 캡션·제목·훅·태그의 검수 및 수정 |
| `grounding-summary.json` | 모든 카드·SNS 문구가 통과한 경우의 검수 목록 |
| `card-copy-02.json` 등 | 검수를 통과한 카드 원고 |

오프셋은 바이트가 아닌 Unicode 문자 기준입니다. `raw_chunk_start/end`로
원문 구간을 읽고 `normalize_quote()`를 적용한 뒤
`normalized_quote_start/end`로 인용을 재현할 수 있습니다.
근거 ID는 최종 `studio-package.json`의 `facts[].key`에도 연결됩니다.
검수 기록과 근거 색인은 Work 전달 ZIP에도 포함됩니다.

관계 검수 보고서는 `schema_version: 2`, `verification_method: fact_relationships`입니다.
각 시도의 `model_verdict.claims`에 검수한 문구와 필드, `batches`에 6개 관계 판정과 오류를 기록합니다.
짧은 근거 번호 E1/E2는 `evidence_map`을 통해 실제 evidence_id에 연결됩니다.
수치 사전검사에서 실패했으면 `model_verdict`는 null이고, 수치 오류를 먼저 수정합니다.
모델 장애 시 `pending_review`에는 이미 끝난 검수 요청의 결과가 남습니다.

`grounding-summary.json`의 passed는 근거 검수 통과이며 게시 승인이나
정확도 확률이 아닙니다. 기존 직원 평균 점수 역시 편집 자체평가입니다.
사후 직원 피드백과 기존 Feedback Memory 동작은 유지하며, 실패한 실행의
피드백은 저장하지 않습니다. 승인된 규칙만 학습하는 기능은 후속 단계입니다.
